Mapa del sistema

Dos clientes, un gateway y cuatro servicios. Dos lenguajes en el backend, una base por servicio y un bus de eventos entre ellos.

Actualizado el 2026-11-25, con lo que está desplegado. El detalle, nivel por nivel, está en los diagramas C4.

Clientes y gateway

Cliente Expo · TypeScript
Una sola base de código para web y Android. La web de producción se sirve desde Vercel (Cloudflare Pages sirve develop como entorno de prueba) y la APK se compila con EAS en cada merge a main.
Backoffice Expo · TypeScript
Para el staff: usuarios, servidores, reportes, métricas, trazas y logs. Se sirve desde Cloudflare Pages.
Gateway KrakenD CE
Única entrada HTTP. Valida el JWT, aplica rate limiting y pasa X-User-Id, X-User-Role y el secreto interno de cada servicio. El tiempo real y el audio no pasan por acá.

Servicios

Autenticación Python
Cuentas, login con contraseña, Google y 2FA, refresh, recupero, perfiles y presencia. Firma los JWT (RS256) y publica su JWKS.
Servidores Python
Servidores, canales, roles y permisos, invitaciones, baneos, silencios, reportes y auditoría. Les responde a mensajes y a voz si alguien puede entrar a un canal.
Mensajes Python
Envío, edición y borrado, historial por cursor, menciones, no leídos y notificaciones. Reparte en vivo por WebSocket.
Voz Go
Canales de voz y llamadas 1 a 1 sobre LiveKit: tokens de sala, presencia en vivo y corte de acceso al banear o silenciar.

Datos

PostgreSQL Supabase
Autenticación y servidores, cada uno con su schema y un usuario que solo puede tocar el suyo.
MongoDB Atlas
Mensajes, indexados por canal y fecha.
Redis Upstash
No guarda datos de negocio: eventos entre servicios, Pub/Sub entre instancias, tickets de WebSocket y presencia.
Cloudflare R2
Avatares, íconos y banners. En la base solo queda la URL.

Infraestructura

Render
Los cuatro servicios y el gateway, como contenedores Docker que se despliegan desde main.
LiveKit Cloud
Media server y TURN. Es la fuente de verdad de quién está en cada sala.
Grafana Cloud
Trazas en Tempo y logs en Loki, con un trace_id que cruza HTTP, eventos y WebSocket.
Brevo y Google
Mails transaccionales y login federado, los dos desde autenticación.
Vercel y Cloudflare Pages
La web del cliente en producción (Vercel), y el backoffice y el entorno de prueba de develop (Cloudflare Pages).

Por qué cada tecnología donde está

El detalle y las alternativas descartadas están en los ADR 0014 y 0015, y las de cada proveedor de la nube, en el ADR 0016.

KrakenD

Un gateway declarativo: todo sale de la configuración, sin código propio que mantener. Cada servicio tiene su archivo de rutas, así que dos personas pueden sumar endpoints sin pisarse.

Python

Autenticación, servidores y mensajes son reglas de negocio, validaciones y permisos sobre I/O. FastAPI genera el OpenAPI desde el código y los tres comparten la misma estructura.

Go

Voz usa el SDK oficial de LiveKit, sostiene WebSockets abiertos con goroutines baratas y es un binario chico que arranca rápido después de dormirse en Render.

PostgreSQL

Cuentas y servidores son relacionales: emails únicos, un miembro por servidor, permisos que se calculan con joins. El outbox se guarda en la misma transacción que el cambio.

MongoDB

Los mensajes se leen casi siempre como "los últimos N de un canal", sin joins, y el documento cambia de forma (menciones, ediciones, borrado lógico).

Expo + TypeScript

Una sola base para web y Android con React Native Web. NativeWind traduce las clases de Tailwind a estilos nativos, y las mismas sirven en la web.
